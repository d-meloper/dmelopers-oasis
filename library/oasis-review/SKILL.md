# Review

## Prerequisites and scope

The requested baseline, exact current source/dirty inputs, edit ownership and relevant source/build or publication proof.

Read the selected project contract and actual tool capabilities. Installation or discovery grants no external authority. Existing human authorization applies only to its exact scope; obtain missing concrete authority before the effect. Preserve core roles and manual owner relay.

## Workflow and recovery

Authenticate the actual comparison. A version, branch name, ancestry or tag alone does not prove public/private projection parity. Inventory the net diff, staged/unstaged and relevant untracked inputs, including additions/deletions and both rename sides. Keep commit and tree object types distinct; commit messages are context, not coverage.

Trace changed contracts into connected unchanged callers, data, timing, teardown and channel paths. Inspect revised tests for weakened expectations. Establish the expected behavior and causal before/after evidence before calling a defect new. Keep suspected and pre-existing issues separate; a read-only request stays read-only and a no-defect review creates no fabricated change.

Make the smallest complete authorized correction at the responsible layer. Refresh only evidence invalidated by source drift and inspect the final net effect. Report user-visible change notes, proven resolutions and actual checks in the owner's language, with manual/unknown limits. Do not create a report ledger, rebuild, scan, launch, publish or send messages solely because a review ran.

Use [acceptance scenarios](references/acceptance.md) for changed decision boundaries. Source/fixture checks, installed behavior and live reflection are distinct. Retain failed, unknown and not-run outcomes. Improve existing project-local guidance from evidence; structural/core changes need approval. No automatic upstream propagation or monitoring.
