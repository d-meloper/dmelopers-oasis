# Artifact Security

## Prerequisites and scope

Exact artifact inventory/hashes, project acceptance policy and an available approved scanner. Hash lookup and uploading bytes have distinct authority.

Read the selected project contract and actual tool capabilities. Installation or discovery grants no external authority. Existing human authorization applies only to its exact scope; obtain missing concrete authority before the effect. Preserve core roles and manual owner relay.

## Workflow and recovery

Select only the requested artifact set and rehash before each external boundary. Inventory coverage is not scan coverage. Determine whether existing evidence is for identical bytes, fresh under the actual policy and based on lookup or an acknowledged upload. Do not import a donor installer-only scope or standing upload permission.

Before upload bind existing human authority to concrete files and destination. Preserve intent, bytes and acknowledgement IDs. Poll within a bounded operation and resume with reads; an uncertain POST or failed receipt write does not authorize another upload. Unknown, pending, malformed, mismatched and unconclusive results stay distinct from passed and failed.

Retain raw categories, engine identities and exact coverage. Apply the configured criterion without relabeling historical reports. A detection is not automatically a false positive; scan acceptance grants neither installed acceptance nor publication. Avoid exposing keys, raw secrets or user data in diagnostics. Recovery inspects the existing operation rather than repeating production or expanding scan scope.

Use [acceptance scenarios](references/acceptance.md) for changed decision boundaries. Source/fixture checks, installed behavior and live reflection are distinct. Retain failed, unknown and not-run outcomes. Improve existing project-local guidance from evidence; structural/core changes need approval. No automatic upstream propagation or monitoring.
