# Published Content

## Prerequisites and scope

Available content connector, exact page/parent or document target, configured release identity, managed content shape and requested language set.

Read the selected project contract and actual tool capabilities. Installation or discovery grants no external authority. Existing human authorization applies only to its exact scope; obtain missing concrete authority before the effect. Preserve core roles and manual owner relay.

## Workflow and recovery

Resolve the requested published release using actual metadata, not local version strings. Bind release/source identity, publication time, complete notes/body and the configured artifact set. Verify stable download URLs and required byte/signature evidence with real available tools; no hardcoded asset type or locale order. Preserve reviewed facts and links rather than inventing missing translations.

Fetch the exact target and parent before composing the narrow update. Preserve unrelated blocks, child objects, properties and manual edits. Ambiguous managed regions or proposed unrelated loss require the owner's concrete decision. Existing authorization remains valid for unchanged scope; a release publication does not automatically authorize this content write.

Re-resolve release/body/assets before mutation. Drift invalidates the prepared payload; download counters alone do not. Update only the matched region, then read back its actual nesting, facts and links. Already matching content is NOOP. Reconcile uncertain writes by reading before retrying. Retain a non-sensitive local receipt; no scheduled posting or upstream follow-up is implied.

Use [acceptance scenarios](references/acceptance.md) for changed decision boundaries. Source/fixture checks, installed behavior and live reflection are distinct. Retain failed, unknown and not-run outcomes. Improve existing project-local guidance from evidence; structural/core changes need approval. No automatic upstream propagation or monitoring.
