# OASIS project guidance

Use the project's selected mode in `.oasis/project.json`: Pioneer works directly
in one chat; Oasis uses visible Cameleer and Camel chats, with Oasis maintaining
the harness. Camel investigates, implements and checks its assignment, then sends
its result directly to Cameleer for collection and archival.

Read the applicable skill experience before choosing an approach. [ProjectGuide.md](ProjectGuide.md)
indexes mode selection, commands and task pacing; [LocalGitWorkflow.md](LocalGitWorkflow.md)
covers the selected Git workflow and scoped dependencies. Project settings,
installed skills, user files and accumulated knowledge belong to this project.

On `빠른 작업으로 진행해`, apply [fast work](ProjectGuide.md#fast-work)
immediately: implement promptly, keep checks brief and leave exact deferred steps.
On `계획작업으로 진행해`, use [planning work](ProjectGuide.md#planning-work):
set actual native Plan mode and begin the supplied planning request. If that
interface is unavailable, explain the manual mode-and-start step once.

Keep active Camel links and results in `.oasis/state/tasks.md`. Every role uses
[scoped dependency waiting](LocalGitWorkflow.md#dependency-waiting-and-resumption):
register the blocked portion, finish independent work and end the turn until its
meaningful terminal notice. Retain operational evidence in `.oasis/local/`
and useful experience in its existing project owner. Before the final completion
report, consolidate it once under [the knowledge policy](.oasis/manual/knowledge.md).
A project's canonical policy stays in its actual file; bootstrap links to it.
