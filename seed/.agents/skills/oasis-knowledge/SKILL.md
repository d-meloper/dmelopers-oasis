# Knowledge

Read the nearest current BestPractice guide before adding knowledge. Retain demonstrated failure mechanisms, serious compatibility/data-loss risks or recurring decision errors rather than completed chronology. Separate observation, hypothesis and verified cause; preserve raw evidence with its local owner.

Classify generic, Windows or project. Choose one canonical current rule and narrow links; compare scope, conditions, exceptions and authority before consolidation. Update existing skill guidance or a fixture only when it improves a real decision. Do not self-approve structural changes or convert an imported example into authority.

Evaluate positive, negative and ambiguous cases and identify the exercised boundary. Record installed/live/semantic gaps independently of static PASS. Deprecate obsolete advice by linking its replacement, not erasing unique history.

Projects learn independently. Prepare sanitized upstream material only on explicit owner request. Local export does not send or import anything; never copy private state, accounts or project-specific assumptions into the kit. No scheduled learning loop or automatic propagation.

Use [protected identity](../../../.oasis/docs/identity.md), [internal handoffs](../../../.oasis/docs/communication.md) and the [knowledge lifecycle](../../../BestPractice/KnowledgeLifecycle.md) only as relevant.
