# Github Publication

Determine whether the request is source-only, release assets, isolated test publication or post-publication work. Select the exact configured repository/account and public-source mode. Private source export requires a complete reviewed allowlist projection; direct-public projects keep their own branch policy. Do not copy private guidance, credentials, local state or unrelated artifacts into public content.

Prepare one immutable candidate from the selected source and actual project producer. Bind source/tree, artifact inventory/hashes, version/channel, reviewed body and allowed remote effects. Source readiness, build completion, scans, installed behavior and publication each require their own evidence; optional checks are not invented mandatory gates. Reuse matching retained bytes, never silently rebuild after approval.

Before writes confirm existing human authorization covers the concrete candidate and target. A JSON approval label is not human approval. Recheck drift, respect repository controls and stop on conflicting existing tags/assets. Do not widen tokens or disable protections. Preserve partial state; reconcile uncertain operations by stable remote identity before retry.

Read back the exact public refs, release and assets; acknowledgement or upload acceptance is insufficient. Test-channel mutability never permits official replacement. Publication does not trigger Notion, mail, installs or backups unless separately within authorized scope.

Use [protected identity](../../../.oasis/docs/identity.md), [internal handoffs](../../../.oasis/docs/communication.md) and the [knowledge lifecycle](../../../BestPractice/KnowledgeLifecycle.md) only as relevant.
