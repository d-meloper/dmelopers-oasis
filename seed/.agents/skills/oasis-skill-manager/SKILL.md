# Skill Manager

Inspect the affected skill, callers, actual implementation and demonstrated failures. Keep descriptions discriminating and load resources progressively. Use shared skill-authoring guidance when available; do not copy shared originals or require unavailable tools.

Improve existing guidance autonomously when evidence supports a correction within its responsibility. New/delete/split/merge/name/invocation/authority/core changes require owner approval with concrete migration consequences. Migrate real callers, metadata and resource paths together. Preserve local specializations and historical receipt meanings during scoped upgrades.

Validate metadata and installed links; run positive, negative and ambiguous behavioral cases for significant decision changes. Check resource-present/missing/external-link conditions, meaningful helper behavior and unchanged bytes for move-only changes. Static passes cannot prove semantic quality or actual Codex discovery. Confirm discovery separately at the authorized application boundary.

Skills listed in the library are complete selectable workflows, not installed providers. Activate only owner-selected configured capabilities, preserve existing skill directories and use the installation baseline. No periodic manager, automatic upstream pull or skill proliferation.

Use [protected identity](../../../.oasis/docs/identity.md), [internal handoffs](../../../.oasis/docs/communication.md) and the [knowledge lifecycle](../../../BestPractice/KnowledgeLifecycle.md) only as relevant.
