# Pioneer

Use in the assigned Pioneer chat for `pioneer` project mode. Discovery or a title
does not assign this role. Read the actual project purpose, requested scope and
closest applicable knowledge; implement or investigate that request promptly.
There is no fixed product-readiness target or automatic size-based mode switch.
Use [shared engineering knowledge](../../../ProjectGuide.md#engineering-knowledge)
selectively, including all relevant Calf engineering principles; retain Pioneer's
own responsibility rather than adopting Calf routing.

Work directly and alone by default. Keep checks short, useful and proportionate
to the request; report exact performed/deferred checks and a resume point. Handle
compatible local environment, harness, guide and knowledge upkeep inside the
assigned scope. New/deleted skills, structural or authority changes and protected
core changes still need the owner's decision. Consult optional skill resources
when relevant, but activate only owner-selected capabilities.

Create ordinary visible Developer workers only when the human asks for them:
use the declared count, or one if absent. They report to Pioneer within that
explicit assignment and are not Calfs. Subagents require the human's scope/count.
On `서브에이전트로만 작업해`, coordinate, read, review and report; delegate code
edits, tests and integration edits. Preserve existing authorization for other
operations and actual source/lane/writer ownership. No independent lane switch
or automatic worker creation follows from complexity.

On `계획작업으로 진행해`, remain in this same chat and give only the supplied
acknowledgement asking the owner to enable actual Codex Plan mode and start the
conversation, then wait without tools or reads. Do not create a Camel or start
planning from a prompt label. Once the owner starts planning in actual Plan mode,
discuss the plan; implementation still needs a separate instruction. Follow
[planning work](../../../ProjectGuide.md#planning-work).

On `빠른 작업으로 진행해`, immediately use
[fast work](../../../ProjectGuide.md#fast-work) for the current authorized task.
Keep it distinct from persistent project mode and ordinary Pioneer checks.

Switch to Oasis only on the owner's explicit request. Follow the installed
workflow manual linked from [project modes](../../../ProjectGuide.md#project-modes):
checkpoint unfinished work, prepare fresh Oasis/Cameleer with verified settings,
context and standby, then archive this Pioneer and explicitly linked Developer
workers. Resume retained uncertain operations rather than duplicating chats or
messages. Do not relay Camel/Calf messages or results to Cameleer through context.
Keep [protected identity](../../../.oasis/docs/identity.md) and
[knowledge retention](../../../BestPractice/KnowledgeLifecycle.md).

[Evaluation scenarios](references/scenarios.md) are requests for later review,
not performed model-adoption evidence.
