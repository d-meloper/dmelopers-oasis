# Coordination experience

## Link work by actual identity

Use visible Camel chats for assignments and retain their actual IDs and useful
context in `.oasis/state/tasks.md`. Titles can change; `camel_A_goal` helps people
scan the list without deciding parentage. Cases K04-K06 in the
[migration reference](../../../../.oasis/manual/migration-lessons.md) distinguish
visible chats from internal subagents, incompatible project IDs and uncertain
creation. A failed create reply is a reason to reconcile that create, not blindly
create another Camel.

## Collect the result once

A Camel's direct completion gives Cameleer the changed scope, relevant checks
and result location. Inspect the actual result and integrate it under the chosen
Git workflow. Reuse matching checks; add checks for changed integration inputs or
specific doubts. K13/K14 show source integration and packaged-byte parity proving
different things; K22 shows why failed or deferred checks need to stay visible.

After collection retain the result link and archive Camel. Restore that same
chat for follow-up. Keep unfinished work available. Retained external intent
case K35 and merged-publication case K38 explain why uncertain effects require
identity reconciliation; duplicate completion must not cause a second merge or
archive cycle. Ordinary result collection is event driven.

## Planning and scoped dependencies

For a planning request, set actual native Plan mode through a supported path,
preserving current model and reasoning, and begin the supplied request. If mode
setting is unavailable, give the manual mode-and-start instruction once.
See [planning work](../../../../ProjectGuide.md#planning-work). Historical K08's
old plan-wait sequence is retired; planning-to-implementation follows the user.

A Windows native trial with Codex 0.162 found that a freshly created Camel had
no saved turn settings yet, and an override-free resume wrote host defaults,
losing the inherited effort and approval selection. Use verified creation
settings for the first input, current saved settings thereafter, and explicitly
preserve them only when a cold recipient needs loading. Keep loaded chats as
they are. See the installed [native adapter](../../../../.oasis/manual/sessions.md)
for the concrete transport and recovery boundary.

For dependencies name the blocked portion, finish independent scope and use the
[one terminal notice](../../../../LocalGitWorkflow.md#dependency-waiting-and-resumption).
K24's whole-checkout consumer shows why connected build/fixture inputs matter
as well as edit paths. Completion, failure and cancellation are terminal results;
routine progress and receipt ACKs do not help that boundary.

## Preserve useful context through mode changes

Retain independent requests and unfinished work while the project's mode changes.
Use actual linked IDs for affected managed chats rather than titles. Keep compact
goals and result references instead of forwarding whole transcripts. K42 observed
overbroad conversation retrieval despite successful file work; a small relevant
range reduces unrelated disclosure.
