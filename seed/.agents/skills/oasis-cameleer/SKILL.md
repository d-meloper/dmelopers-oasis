# Cameleer

Answer ordinary questions directly. Distinguish a new bundle from follow-up, progress or requested collection; only the new bundle needs one Camel. Reuse existing Camel ownership for corrections and resumption. Prepare the selected Git profile's actual readiness first; for main/test feature work select test through acknowledged ownership before execute or plan-wait delivery.

Owner-established independent specialty requests in Oasis mode follow the single [independent session contract](../../../LocalGitWorkflow.md#independent-specialist-sessions). Preserve those requests outside the bundle hierarchy; do not absorb, dispatch or collect them automatically. Keep actual urgent-transition and shared-checkout responsibilities within the owner's scope.

Create persistent Codex project chats through supported session tools, preserving verified model/permissions and exact title. Carry actual human request, scope, completion criteria, source/lane, writer boundary and reporting prohibition. Reconcile unknown create outcomes before retrying. Never substitute internal subagents for visible roles or hardcode a model.

On `계획작업으로 진행해` for coordinated bundle work, immediately select [Planning work](../../../ProjectGuide.md#planning-work) without another mode-choice question. Assign/reuse the bundle's Camel with `mode: plan-wait`. Put the tool-free waiting acknowledgement and request for an actual Codex Plan mode conversation in the initial handoff itself; the Camel must not read guidance first. An established independent Oasis chat waits in its own chat under the linked contract. Do not claim the native mode changed or start planning/implementation on the owner's behalf.

On owner-requested collection inspect exact selected lineage, actual patches, compatibility, ownership and source-bound evidence. Batch common checks once; missing evidence keeps the batch open and partial collection needs the owner's subset decision. Integrate under serialized Git ownership. Archive confirmed Calfs before Camel only when requested and verified. Do not solicit descendant messages: the human manually relays results here.

Use [protected identity](../../../.oasis/docs/identity.md), [internal handoffs](../../../.oasis/docs/communication.md) and the [knowledge lifecycle](../../../BestPractice/KnowledgeLifecycle.md) only as relevant.
