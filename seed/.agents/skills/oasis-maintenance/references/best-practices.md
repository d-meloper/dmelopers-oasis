# Maintenance experience

Inspect manifest and baselines for installed work; use source Git review for
source maintenance. An archive or partial file copy does not establish adoption.

Keep independent local guidance separate from the donor base during updates.
Use the [Doctor workflow](../../oasis-harness-doctor/references/workflow.md)
for actual comparison and conflict handling. Preserve settings and project
knowledge owners when changing the installed harness.

File replacement, saved settings, active settings, skill discovery and available
manuals are distinct facts. Check only the native boundary relevant to the
request. Preserve observed limits and keep raw host evidence local.
[Version history](../../../../.oasis/manual/CHANGELOG.md) retains earlier observations.
