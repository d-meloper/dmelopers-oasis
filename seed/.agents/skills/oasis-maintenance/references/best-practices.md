# Maintenance experience

A source checkout and an installed project have different ownership. K02 and K27
in the [migration reference](../../../../.oasis/manual/migration-lessons.md) show
that archive coverage or partially copied files did not establish installation.
Inspect the manifest/baselines for installed work; use source Git review for
source maintenance.

K28 demonstrates why independent local guidance must remain distinct from its
donor base during updates. Refresh owned files through the existing comparison
and conflict handling, keeping installed skills and project knowledge. Use
[Doctor's workflow](../../oasis-harness-doctor/references/workflow.md) for that task.

K39-K41 distinguish saved/active native settings, CLI reporting and discoverable
skills from available manuals. File replacement does not establish that an
existing chat adopted the change; check only the native boundary relevant to the
requested application. Portable maintenance knowledge keeps the mechanism and
its observed limits, while raw host evidence stays local.
