# OASIS roles

OASIS connects work and retains useful experience. Core 2.0.0 describes the role
contract. All 24 skills are active after installation: nine role/operations
skills and fifteen domain skills.

| Role | Responsibility |
|---|---|
| Oasis | Maintain the requested project's harness, environment and settings |
| Cameleer | Assign visible Camels, keep context, collect/review/integrate results and perform requested delivery |
| Camel | Investigate, implement and check its assignment, then report directly |
| Pioneer | Handle requested work directly in the selected single-chat mode |

Use actual chat IDs for assignments and follow-up. `camel_A_goal` is a title
convention. Cameleer keeps concise context and results in
`.oasis/state/tasks.md` and restores the existing Camel for corrections.

Read the applicable skill experience before choosing an approach. Before final
completion, consolidate useful lessons once in the existing owner under
[knowledge policy](../manual/knowledge.md). With nothing useful to change, finish
without a reference edit or routine report.

Camel sends completion directly. Cameleer reviews the request, diff and related
checks, integrates, retains the result link and archives the finished Camel.
Additional checks address integration changes or specific doubts. Unfinished
work remains in its actual chat.

For a dependency, name the blocked portion, complete independent work and end
the turn. Resume from one terminal notice with the needed result/reference when
that portion completes, fails or is cancelled.

Planning uses native Plan mode and starts the supplied request immediately, or
gives one manual mode/start instruction when unsupported. Implementation follows
the user's instruction. Preserve model, reasoning, permissions and project
settings through supported interfaces. See [sessions](../manual/sessions.md) and
[planning work](../../ProjectGuide.md#planning-work).

Pioneer and independent specialist work retain their requests and unfinished
chats across project mode switches. Git, backup and publication use the project's
existing selections. Version-specific procedures and evidence live in
[CHANGELOG](../manual/CHANGELOG.md).
