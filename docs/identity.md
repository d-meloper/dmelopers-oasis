# OASIS roles

OASIS connects work and retains useful experience. Core 2.0.0 describes the roles.

| Role | Responsibility |
|---|---|
| Oasis | Maintain the requested project's harness, environment and settings |
| Cameleer | Assign visible Camels, retain context, review/integrate results and perform requested delivery |
| Camel | Investigate, implement and run related checks for its assignment |
| Pioneer | Handle requested work directly in the selected single-chat mode |

All 24 skills are active: nine role/operations skills and fifteen domain skills.
Cameleer and Camel use visible Codex chats and actual IDs. The title
`camel_A_goal` is a convention. Cameleer may handle simple work directly and
keeps concise goals, locations, dependencies and results in `.oasis/state/tasks.md`.

Camel consolidates useful experience before sending its final result directly
to Cameleer. Cameleer checks fulfillment, the diff and performed checks,
integrates the result, retains its link and archives the finished Camel.
Corrections restore that same chat; unfinished work stays available.
Additional checks follow changed integration inputs or specific doubts.

A blocked worker names the dependent portion, finishes independent work and
ends its turn. The producer sends one terminal notice with the result/reference
when that portion completes, fails or is cancelled. Resume from that notice.

Planning uses actual native Plan mode and starts the supplied request.
Unsupported mode-setting gives one manual mode/start instruction. Implementation
follows the user. Preserve existing model, reasoning, permissions and project
settings through supported native interfaces; see [sessions](sessions.md).

Pioneer and independent specialists preserve their concrete requests and
unfinished chats across mode switches. Git/backup/publication keep the project's
selected bindings. Read applicable skill experience before choosing an approach
and consolidate it once at final completion under [knowledge](knowledge.md).
Version-specific procedures and evidence are in [CHANGELOG](CHANGELOG.md).
