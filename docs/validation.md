# Verification boundaries

Run local tests from the source root:

```powershell
python -B -X utf8 -m unittest discover -s tests -t . -v
```

Tests use disposable filesystem/Git projects and injected native/service adapters.
They verify the exercised functions, not live chat adoption or remote effects.
Select affected modules for ordinary changes; shared/unknown Python uses the
full suite when existing passing evidence does not cover the same inputs.
Reuse passed checks with matching code, tests, configuration and other consumed
inputs. Version/documentation changes alone do not invalidate unaffected
functional checks. Run checks for changed inputs and retain honest failed,
missing or deferred coverage. Exact final export/privacy/identity checks still
apply to the candidate being delivered. Source delivery accepts a retained
verified build receipt explicitly; it does not turn a bare log or failed run
into a pass.

| Surface | Local verification | Separate live evidence |
|---|---|---|
| Install/update | All 24 active skills, three-way conflicts, recovery and preserved local Calf knowledge/settings | Actual adopter conflicts, discovery and chat adoption |
| Roles/tasks | Actual-ID assignment, title changes, direct completion, collection/archive/restore and task-list updates | Visible chats, real completion arrival and integration |
| Dependencies | One terminal notice, failure/cancellation, duplicates and uncertain-send recovery | Ended-turn idle and authorized follow-up |
| Plan | Supported settings/update or turn/start mode fields and manual fallback | Actual native Plan selection and model planning |
| Project modes | Preserved selection, interrupted transitions and unfinished/independent work | UI navigation and native archive cascades |
| Git/backup | Disposable branches, refs/index preservation, backup and inactive restore | Selected repository identity, exact snapshot and affected restore |
| Publication | Exact projection, privacy, PR/squash and uncertain responses | Checked head, merged tree and anonymous readback |
| Knowledge/skills | Metadata, resource links, activation and free-form notes | Appropriate model selection and useful application |

Core 2 metadata describes roles and versions. Tests do not enforce behavioral
packet fields, report wording, title syntax, ownership ACKs, approval records,
core content hashes or document length. Preserve real input validation,
filesystem collision/link protection, concurrency, settings and native errors.

Finish ongoing Camel/Calf work before Core 2 migration. Verify baseline retirement,
local knowledge preservation, mode/Git/settings and historical links.
Fixtures do not establish that a live legacy chat has finished.

`빠른 작업으로 진행해` selects brief relevant checks and exact deferred commands
under installed `ProjectGuide.md`'s fast-work rule. Report not-run coverage.
Read-only protocol schemas establish field availability only; source implementation
does not create diagnostic chats or live model turns. Separate requested live
trials need their concrete scope, settings and cleanup.

For dependency costs, separate elapsed wait, tool wait and model requests.
Count distinct native usage response IDs; cached input and reasoning output are
subsets. Missing telemetry is unknown. A local duplicate guard prevents repeated
integration, but cannot prevent every duplicate native message invoking a model.

Historical v1 trials exercised original role chats, Calf-to-Camel reporting,
discovery, recovery and isolated publication. They do not verify Core 2 direct
completion, automatic collection, Plan or migrated chat adoption.
[Migration lessons](migration-lessons.md) retain mechanisms and limits.

An owner-requested Core 2 trial on Windows with Codex 0.162.0-alpha.17.2 used
real native chats, model turns and an isolated adopter. Native Plan produced a
plan item without changing the fixture; both the first input of a fresh Camel
and a resumed Camel preserved inherited settings. Camel sent completion
directly, Cameleer inspected the result and collected/archived it, and follow-up
restored the same ID and retained history before another completion/archive.
Native message IDs and archived-list readback verified those effects. This is
backend and model evidence, not a visual toolbar check, active-turn steering,
descendant archive test or legacy-chat migration demonstration. The trial used
an explicitly owned loopback server; the production transport limitation is
documented in [sessions](sessions.md). Private trial receipts stay local.

Windows fixtures reproduce replacement-blocking readers. Atomic writes retry
only errors 5 and 32 with the same flushed temporary bytes, at most six attempts
and 0.62 seconds of delay, rechecking links each time. Permanent failures preserve
old bytes. This does not identify an earlier holder or prove live publication.
See [Windows sharing semantics](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew).

Reports identify what ran, failed, remains uncertain and was deferred.
Static inventory/links are distinct from installed runtime and model adoption.
